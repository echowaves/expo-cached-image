## expo-cached-image

Cached image component for React Native: downloads a remote image into the Expo filesystem cache and serves subsequent renders from disk. TypeScript, React Native, Expo, npm. BMad planning and tickets live in `_bmad-output/`.

## Policy

- Never add a dependency without explicit approval — solve it with existing dependencies or built-in APIs first.
- Add or update dependencies at exact versions (`1.2.3`, never `^1.2.3`) using `npm install --save-exact`.
- Never hand-edit `lib/` — it is generated by `tsc` and gitignored. Change `src/`.

## Where things are

- Component and caching logic: `src/index.tsx`; cache paths and constants: `src/consts.ts`.
- The `CachedImage` props are the public API — changing them breaks consumers.

## Running and verifying

- `npm run build` compiles with `tsc`; `npm run lint` runs ts-standard; `npm test` runs jest.
- `npm test` passes vacuously — `__tests__/` is empty, so a green run proves nothing. Verify changes with `npm run build`, `npm run lint`, and a real consumer app.

## Conventions that differ from defaults

- The package `version` tracks the Expo SDK major it targets (`57.0.0` ↔ Expo 57).
- Supporting a new Expo major means bumping devDependencies, the `expo`/`expo-file-system` peer window, and the package version together; consumers on dropped SDK majors stay on the older release line.
